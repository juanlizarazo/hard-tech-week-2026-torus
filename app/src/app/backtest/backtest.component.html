How the month was replayed

  • The simulated site ({{ result.summary.siteName }}, seed {{ result.summary.seed }}) runs every 15 minutes of {{ model.monthLabel }} on {{ result.summary.scheduleName }}.
  • No storage is the bill with the Torus Station switched off.
  • The {{ model.shaverName.toLowerCase() }} discharges whenever load passes {{ formatNumber(result.summary.naiveTargetKw) }} kW and recharges below it. It reads no prices or forecasts.
  • {{ model.leadName }} re-solves the LP each afternoon for the next day on a load forecast: for each 15 minutes, the highest load on the same weekday over the last four weeks. Prices and carbon are known a day ahead.
  • It then runs that plan against the real load with a live cap. When the site would pass the plan's peak or the month's peak so far, Pulse ramps up within its limits and Spin covers the rest, without touching the Wattsmart reserve. If stored energy runs short, the planned discharge is cut. State of charge (how full each machine is) carries from day to day.
  • {{ model.leadName }} with a perfect load forecast is the same planner told each day's real load in advance, with no live cap. It shows what forecast error costs.
  • {{ model.oracleName }} solves the whole month at once with the real loads. No real controller can match it; it is the ceiling for the capture rate.
  • Bills use base rates only. Riders are excluded.
